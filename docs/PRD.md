# 제품 요구사항

[시작 안내](../README.md) · 근거: [기획 원문](../plan.md) §3–4, §10–11

## 목적과 사용자

단일 업종(업종명 미정, [D10](DECISIONS.md))의 소상공인이 남은 재고를 간편하게 게시하고, 주변 소비자가 할인 상품을 예약해 현장에서 결제·수령하도록 합니다. 개발 총괄 1명과 프론트엔드 팀원 3명이 하나의 웹 프로젝트에서 협업합니다.

## 기능별 완료 조건

| ID | 기능 | 우선순위 | 완료 조건 | UI 담당 |
| --- | --- | --- | --- | --- |
| F01 | 사진 기반 상품 분석 | P0 | 사진·마감 시간 입력 후 상품명·수량·단위·외관 상태·불확실성을 표시 | A |
| F02 | 분석 결과 수정·게시 | P0 | 판매자가 결과·기준가·최저가·종료 시점을 확인하면 실제 DB에 게시 | A |
| F03 | 동적 가격 | P0 | 조회 시 서버가 실제 데이터로 계산하고 최저가를 보장 | A/B, 로직은 총괄 |
| F04 | 예약 관리 | P0 | 예약은 즉시 확정되고 판매자가 판매 완료·취소·노쇼 처리하며 재고와 판매 내역이 일치 | A |
| F05 | 기본 판매 리포트 | P1 | 등록·예약·완료 건수, 판매 수량·매출·잔여 재고를 실제 데이터로 집계 | C |
| F06 | 지역별 탐색 | P0 | 직접 선택한 지역의 판매 중 상품 제공 | B |
| F07 | 상세·픽업 예약 | P0 | 서버가 최신 가격·재고·시간을 확인하고 요청 시 가격 확정·재고 확보 | B |
| F08 | 나의 예약 | P0 | 본인의 확정·취소·판매 완료 상태와 방문 정보 표시 | B |

인증 화면은 C, Supabase Auth 연동·역할·서버 권한 검증은 총괄 담당입니다. 판매자 상품 관리에는 재고와 예약 현황 표시가 포함됩니다. 이미 예약된 상품의 수량 수정 규칙은 [D08](DECISIONS.md) 확정 후 구현합니다.

## 핵심 사용자 흐름

판매자 로그인 → 사진 업로드·분석 → 판매자 수정·확인 → 상품 게시 → 소비자 지역 선택·조회 → 픽업 예약(즉시 확정) → 방문·현장 결제·수령 → 판매 완료 → 리포트 반영.

AI는 외관에 근거한 제안을 제공합니다. 식품 안전성이나 실제 유통기한을 확정하지 않으며 가격도 결정하지 않습니다. 분석 실패는 오류로 표시하고 가상의 성공 결과를 만들지 않습니다.

## 제외 범위

서버에 저장하는 위치 이력, 온라인 결제, 배송·배달, 푸시 알림은 MVP에서 제외합니다. AI 리포트 해석은 P2 선택 기능이며 현재 작업표에 포함하지 않습니다. 매장 주소 입력의 네이버 지도 API는 이후 추가합니다([D11](DECISIONS.md)).

## 완료 판정

P0 핵심 거래 흐름을 먼저 완성합니다. P1 리포트는 이후 진행하되, 기획서 §11의 최종 시연 완료 판정에는 리포트까지 포함합니다. 정적 화면이나 Mock만으로 완료를 선언하지 않습니다.
