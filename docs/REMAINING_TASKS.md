## ⚠️ 다음 작업 전 필수

**소비자 상품 목록·상세 API를 시작하기 전에 아래 두 가지를 끝냅니다. 빠뜨리면 상품 조회가 실패하거나 검증용 상품이 소비자 화면에 노출됩니다.**

1. **원격 DB에 `recent_approved_quantities` 함수를 추가합니다.** `supabase/schema.sql`의 해당 `create function`부터 `grant execute`까지를 SQL Editor에서 한 번 실행합니다. 스키마 전체를 실행하면 안 됩니다.
2. **검증용 상품 2개를 삭제합니다.**

   ```sql
   delete from public.products
   where id in (
     '7a0a726e-0fee-4ee8-a8b6-5a25bfc79b4f',
     '00f61899-3b12-4004-afb6-46f1cd184ea4'
   );
   ```

**알고 진행할 가격 제한:** 매장에 영업 시작 시각이 없어 새벽에도 오늘 마감 전이면 판매 중으로 계산합니다. 오늘 마감 뒤에 게시한 상품은 판매 종료가 내일이어도 자정까지 판매 종료입니다.

## 3. 남은 검증

- 소비자 계정: `/api/me`, `/seller/*` 차단, 매장·상품 등록 차단.
- 다른 판매자 계정: 타 매장 수정·조회 차단.
- 브라우저: `/store`, `/seller/publish`의 입력, 시간 변환, 모바일 화면.
- Vercel 배포 연결과 환경 변수.

## 4. 정리할 것

- 공개 배포의 소비자 데모 데이터는 4번 작업에서 제거합니다.
- 소비자 데모의 꽃 상품은 D10 확정 후 정리합니다.
- `PATCH /api/seller/store`의 빈 요청은 전용 문구 대신 일반 안내를 반환합니다.
- 운영 전 이메일 인증을 다시 켜고 외부 SMTP와 Redirect URLs를 설정합니다.
- 브랜치 보호를 확인합니다(D09).
- Vercel의 `NAVER_MAPS_CLIENT_ID`를 `NEXT_PUBLIC_NAVER_MAPS_CLIENT_ID`로 추가하고 재배포한 뒤, `https://cohackathon.vercel.app`을 NCP Web 서비스 URL에 등록합니다.
