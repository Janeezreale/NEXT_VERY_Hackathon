# 판매자 대시보드 UI 데모

A03의 상품·예약 관리 진입을 돕는 운영 요약 화면입니다. API·DB·인증·집계 계약은 연결하지 않았으며 A03 전체 완료를 의미하지 않습니다.
이번 변경은 `dashboard/` 내부로 한정합니다. 기존 상품 화면·리포트·예약 화면·공통 파일은 변경하지 않습니다.

## 구성

- 판매 중 상품(마감 임박 포함), 승인 대기, 픽업 대기 요약. 표시된 데모 상태를 기준으로 건수를 세며 실제 시간·영업 정책은 판정하지 않습니다.
- 예약 상태 필터와 읽기 전용 요청 상세 모달. 승인·거절·재고 차감·판매 완료 처리는 없습니다.
- 상품별 단위를 유지한 남은 재고. 개/팩/봉지 등의 수량을 합산하지 않습니다.
- 상품 관리·예약 관리·리포트로 이동. 예약·리포트 UI 추가 요청에 따라 내비게이션 링크와 격리 미리보기 복사 범위만 확장했습니다.
- 로딩·빈 화면·오류·재시도 상태 선택기. 실패 시 데모 데이터를 성공 응답으로 대체하는 동작은 없습니다.

예약 데이터는 대시보드의 `demo-requests.ts`에 분리된 명시적인 개발용 예시입니다.
상품·가게 초기 예시는 기존 상품 데모 파일을 읽기 전용으로 재사용합니다. 가게 운영 정책은 초안으로만 표시합니다.
모든 날짜·건수·금액은 고정 시안이며 실제 오늘의 기록이 아닙니다. 매출·순이익·정산액·확정 폐기량을 추정하지 않습니다.
상품 화면의 메모리 내 수정은 페이지 이동·새로고침 후 보존하지 않습니다. 공통 영구 상태·저장 기능은 추가하지 않았습니다.

## 미리보기

프로젝트 루트에서 Node.js 24 / npm 11과 설치된 의존성을 사용합니다.

```sh
node 'src/app/(seller)/seller/dashboard/preview.mjs'
```

http://127.0.0.1:3101/seller/dashboard 에 접속합니다. 같은 서버의 `/seller/products`로 이동할 수 있습니다.
OS 임시 폴더에 판매자 네 화면과 임시 루트 레이아웃을 생성하므로 원본 공통 파일은 바뀌지 않습니다.
Ctrl+C로 종료합니다. 소스 변경 후에는 미리보기를 재시작해야 합니다.

```sh
node 'src/app/(seller)/seller/dashboard/preview.mjs' --build
```

## 확인할 항목

320 / 390 / 768 / 1024px 폭, 200% 확대, 긴 상품명, 탭 키·Escape·모달 포커스 복귀를 점검합니다.
승인 대기 필터는 요청 2개, 픽업 대기 필터는 요청 1개를 표시합니다.
상세에서 실제 처리 버튼 없이 읽기 전용 데모임을 확인합니다.
화면 상태를 바꾸면 운영 지표와 요청이 숨겨지고 각 상태에 맞는 안내가 표시되어야 합니다.

공통 UI가 아직 없으므로 디자인 문서의 토큰 값을 화면 전용 CSS Module에 적용했습니다. 새 공통 디자인 시스템은 만들지 않았습니다.
Pretendard 자산은 추가하지 않으며 설치되지 않은 환경에서는 시스템 폰트를 사용합니다.

## 이번 검증 결과

- `npm run test:run`: 전체 13개 통과. 대시보드 6개는 상태 필터·상품 단위·로딩/빈 화면/오류에서 예시 지표 미노출을 확인합니다.
- `npm run lint`: 오류 0, 기존 `postcss.config.mjs` 경고 1건.
- `preview.mjs --build`: 대시보드·상품 화면 컴파일, TypeScript 검사, 정적 페이지 생성 통과.
- `/seller/dashboard`: HTTP 200, 데모 안내·요약·예약 요청·재고·상품 이동 링크 렌더링 확인.
- `npm run typecheck`: 기존 빈 customer 페이지로 생성된 validator의 TS2306 / TS2344 오류가 발생합니다.
- `npm run build`: 기존 공통 루트 레이아웃 부재로 실패합니다. 담당 범위 밖 파일은 추가하지 않았습니다.
- 브라우저의 실제 클릭·모달 포커스·반응형·스크린리더 검증은 미실행입니다. 위 확인할 항목에 따라 수동 점검이 필요합니다.
