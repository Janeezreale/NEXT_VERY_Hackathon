# 동적 가격 정책과 검증 사례

[시작 안내](../README.md) · 근거: [기획 원문](../plan.md) §6

가격은 서버 규칙 엔진 담당입니다. AI나 브라우저가 가격을 정하지 않습니다. 아래 할인율은 해커톤 가설이며 검증된 시장 수치가 아닙니다.

| 요소 | 조건 | 할인율 변화 |
| --- | --- | --- |
| 상태 | 싱싱 / 오늘 안에 판매 권장 / 내일 폐기 예정 | 0 / +8 / +15%p |
| 마감 | 2~4시간 남음 | +5%p |
| 마감 | 2시간 이하 남음 | +12%p |
| 수요 | 등록 1시간 경과 + 최근 60분 승인 수량 0개 | +5%p |
| 수요 | 최근 60분 승인 수량 2개 이상 | −3%p |

최종 할인율은 상태·마감·수요 보정의 합을 0~100%로 제한합니다. 기준가에 할인율을 적용하고 판매자 최저가를 하한으로 삼아 원 단위로 반올림합니다. 원문 예시: 기준가 10,000원, 내일 폐기 예정, 마감 1시간, 수요 보정 없음, 최저가 7,000원 → 7,300원.

## 적용 규칙

- 상품 조회 시 실제 현재 시각·저장된 승인 수량으로 계산합니다.
- 수요는 예약 건수가 아닌 승인된 **수량**입니다. 임의 수요를 생성하지 않습니다.
- 예약 요청 시 서버가 다시 계산해 확정 단가·총액을 저장합니다. 이후 가격 변경은 기존 예약에 반영하지 않습니다.
- 마감·판매 종료 이후 예약을 차단합니다. 표시 가격 계산과 예약 가능 여부를 혼동하지 않습니다.
- 설정값은 중앙에서 관리하고 화면마다 복제하지 않습니다.

## 경계 정책 — D02에서 확정할 제안

정확히 2시간일 때 +12%p, 2시간 초과~4시간 이하에서 +5%p, 4시간 초과에서 0%p를 적용하는 상호 배타적 구간을 제안합니다. 원문은 정확히 2시간에서 구간이 겹치므로 총괄이 확인합니다.

등록 경과 60분의 포함 여부, 최근 60분의 시작 경계 포함 여부, 승인 후 취소된 수량의 수요 포함 여부, 매장 마감과 상품 판매 종료 중 가격 계산 기준도 확정해야 합니다. 해당 테스트는 정책 확정 후 기대값을 고정합니다.

## 총괄의 자동화 테스트 목록

| 사례 | 기대 결과 |
| --- | --- |
| 원문 예시 | 7,300원 |
| 같은 조건, 최저가 8,000원 | 8,000원 |
| 싱싱·마감 4시간 초과·승인 수량 2개 | 음수 할인 보정을 0%로 제한해 기준가 유지 |
| 기준가 999원·상태 할인 8%만 적용·낮은 최저가 | 919원 |
| 최근 승인 1건의 수량이 2개 | 건수가 아닌 수량 기준의 −3%p |
| 마감 2시간·4시간의 직전/정확히/직후 | 확정한 구간에 정확히 한 번만 해당 |
| 등록 60분·최근 승인 60분의 경계 | D02 결정에 일치 |
| 기준가보다 큰 최저가, 음수 금액 | 입력 오류 |
| 예약 후 현재 가격 변동 | 예약 확정 단가·총액 유지 |
| 판매 종료 시각 도달 | 신규 예약 차단 |

이 문서는 테스트 명세이며 테스트 코드는 아직 없습니다.
