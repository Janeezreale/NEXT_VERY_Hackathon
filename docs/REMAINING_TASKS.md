## 3. 남은 검증

- 소비자 계정: `/api/me`, `/seller/*` 차단, 매장·상품 등록 차단.
- 다른 판매자 계정: 타 매장 수정·조회 차단.
- 브라우저: `/store`, `/seller/publish`의 입력, 시간 변환, 모바일 화면.
- Vercel 배포 연결과 환경 변수.

## 4. 정리할 것

- 검증 데이터를 SQL Editor에서 삭제합니다. 상품 `[검증] 전체 흐름 수정`(`f314b251-3bd6-4897-afd1-f7291059d78a`)과 연결된 판매 기록·예약을 함께 지웁니다.
- Supabase 프로젝트 리전을 확인하고 Vercel 함수 리전(`iad1`)을 맞춥니다. 판매자 화면 속도에 영향을 줍니다.
- 연락처 보관 기간과 파기 방법을 정합니다(D13).
- `products.min_price`는 공개 API에서 뺐지만 공개 키로 DB를 직접 조회하면 읽을 수 있습니다. 비로그인 가격 계산을 서버 전용 경로로 옮겨야 막을 수 있습니다.
- `PATCH /api/seller/store`의 빈 요청은 전용 문구 대신 일반 안내를 반환합니다.
- 운영 전 이메일 인증을 다시 켜고 외부 SMTP와 Redirect URLs를 설정합니다.
- 브랜치 보호를 확인합니다(D09).
- Vercel의 `NAVER_MAPS_CLIENT_ID`를 `NEXT_PUBLIC_NAVER_MAPS_CLIENT_ID`로 추가하고 재배포한 뒤, `https://cohackathon.vercel.app`을 NCP Web 서비스 URL에 등록합니다.
