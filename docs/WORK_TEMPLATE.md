# 작업 카드와 AI 요청 템플릿

[시작 안내](../README.md) · [작업 선택](TEAM_TASKS.md)

GitHub Issue 또는 팀 작업 문서에 아래 양식을 복사합니다. 실제 담당자가 채운 카드가 없으면 예시를 완료된 작업으로 취급하지 않습니다.

## 작업 카드

- 작업 ID / 이름:
- 담당자 / 상태 / 브랜치 / PR:
- 사용자 목표:
- 근거: PRD 기능 ID와 계약 문서 항목:
- 선행 작업과 완료 여부:
- 수정 허용 경로:
- 필요한 API·공유 타입:
- 화면 상태: 정상 / 로딩 / 빈 결과 / 오류 / 권한 없음:
- 완료 기준(사용자 행동으로 확인 가능하게):
- 검증 방법:
- 결정 필요 사항:
- 다음 담당자에게 전달할 내용:

## 구현 시작 전 명세 요청 — 지금 사용 가능

```text
프로젝트 루트의 README.md, AGENTS.md, docs/PRD.md, docs/TEAM_TASKS.md를 읽어줘.
내 역할은 [A/B/C/총괄], 작업 ID는 [ID]야.
관련 docs/API_CONTRACT.md와 docs/DECISIONS.md도 확인해줘.
아직 코드를 작성하거나 패키지를 설치하지 말고,
담당 화면의 사용자 흐름, 필요한 필드, 화면 상태, 완료 조건을 작업 카드로 정리해줘.
기획에 없는 정책과 확정된 요구사항을 구분하고 선행 작업을 표시해줘.
```

## 향후 구현 요청 — 계약·환경 준비 후 사용

```text
현재 프로젝트의 README.md, AGENTS.md, docs/PRD.md, docs/TEAM_TASKS.md를 먼저 읽어줘.
내 역할은 [역할], 작업 ID는 [ID]야. 아래 작업 카드 범위만 구현해줘.

[작성한 작업 카드 붙여넣기]

관련 docs/API_CONTRACT.md, docs/DATA_MODEL.md, docs/PRICING.md와 docs/DECISIONS.md를 확인해줘.
선행 작업과 필요한 계약이 확정되어 있는지 먼저 확인해줘.
미정 업무 정책이 구현에 필요하면 해당 부분을 임의로 정하지 말고 알려줘.
수정 허용 경로를 지키고, 총괄이 제공한 공유 타입과 API 호출 방식을 사용해줘.
실제 데이터를 상수 배열로 대체하지 말고 실패를 가짜 성공으로 처리하지 마.
모바일 화면의 로딩·빈 결과·오류·재시도 상태를 포함해줘.
변경 파일, 완료 기준별 검증 결과, 미실행 검증, 남은 문제를 보고해줘.
```

## 역할별 요청에 추가할 문장

| 역할 | 추가할 문장 |
| --- | --- |
| A | AI 결과는 판매자가 수정·확인하게 하고, 기준가·최저가·판매 종료 입력을 검증해줘. 서버 가격·예약 로직은 수정하지 마. |
| B | 서버가 제공한 현재가와 예약 확정가를 구분해줘. 수량 부족·마감·가격 변경·본인 예약 접근 오류를 처리해줘. |
| C | 공통 컴포넌트를 재사용할 수 있게 정리하고 인증 로직은 총괄 연결 방식을 따라줘. 리포트는 실제 집계 API를 사용해줘. |
| 총괄 | RLS·서버 권한, 트랜잭션·중복 처리, 가격 경계를 검증하고 계약과 공유 타입을 함께 갱신해줘. |
