# 판매자 상품 UI 데모 · A03 일부

상품 카드, 상태 필터, 수정 폼, 로딩·빈 목록·오류 화면의 개발용 미리보기입니다.
API 계약과 무관한 데모 전용 모델을 사용합니다. DB·API·인증 호출 및 브라우저 영구 저장은 없습니다.
상품 상태는 고정 예시이며 수량·시간으로 판정하지 않습니다. 수정 필드는 시안일 뿐 허용 정책을 확정하지 않습니다.
상품 수정 모달은 상품 정보·가격 정보·가게 운영 정보를 분리합니다.
가게 이름·주소·영업시간·예약 접수 마감과 정책 초안은 목록 상단의 공통 운영 정보에 한 번 표시합니다.
`가게 정보 수정 · 데모`에서 공통 표시 문구를 변경할 수 있습니다. 데모 반영 시 모든 상품 카드와 상품 수정 폼이 같은 메모리 상태를 참조합니다.
취소·Escape는 반영 전 초안을 버리고 새로고침하면 모든 변경이 초기화됩니다. 실제 가게 설정·저장·예약 제한은 없습니다.
상품 수정 모달에는 공통 마감 참조 안내만 표시하며 가게 시간·날짜 입력은 없습니다.
정상 판매가·최저 판매가·현재 판매가는 각각 고정 예시값을 읽기 전용으로 표시합니다. 가격 계산·가격 수정·저장은 없습니다.
가게 이름·주소·영업시간·예약 접수 마감의 초기값은 `demo-store.ts`의 별도 표시값을 전달받습니다. 가게 설정 API 호출이나 실패 시 대체 처리는 없습니다.
`영업 종료 30분 전 예약 접수 마감`은 총괄 승인 전 정책 초안으로만 안내합니다.
기존 상품별 가게 마감 입력·30분 전 계산과 관련 테스트를 제거했습니다. 실제 가게 설정 저장·예약 제한·상품별 종료 시점 편집은 구현하지 않습니다.
공통 정보의 수정은 데모 표시 문구만 대상으로 하며, 영업시간 변경 시 예약 접수 마감을 계산하거나 정책과의 일치 여부를 판정하지 않습니다.

## 실행

프로젝트 루트에서 Node.js 24 / npm 11 환경으로 실행합니다.

```sh
npm ci
node 'src/app/(seller)/seller/products/preview.mjs'
```

http://127.0.0.1:3100/seller/products 에 접속합니다. Ctrl+C로 종료합니다.
미리보기는 실행 시 소스를 임시 폴더로 복사합니다. 소스 변경 후에는 기존 미리보기 서버를 종료하고 위 명령을 다시 실행해야 합니다.
루트 레이아웃이 없어도 실행할 수 있도록 OS 임시 폴더에 격리된 Next 앱을 생성합니다.
원본 프로젝트의 공통 파일을 생성하지 않습니다. 서버는 localhost에만 열립니다.
원본 프로젝트의 루트 레이아웃·스타일이 준비된 후에는 일반 개발 서버의 `/seller/products`로 접속할 수 있습니다.

## 확인 순서

1. 320 / 390 / 768 / 1024px에서 카드·긴 상품명·수량·가격 줄바꿈을 확인합니다.
2. 상태 필터를 선택하고 상단 선택기로 로딩·빈 목록·오류를 확인합니다.
   `가게 정보 수정 · 데모`에서 영업시간·예약 접수 마감 표시를 바꾸고 반영하면 상단과 모든 카드·상품 수정 폼에 같은 공통 마감이 표시되는지 확인합니다. 취소·Escape 시 초안이 반영되지 않는지도 확인합니다.
3. 상품 수정 폼에서 이름과 수량 예시를 바꾸고 `데모 변경 미리보기`를 누릅니다.
   정상 판매가·최저 판매가·현재 판매가가 읽기 전용이고 가게 정보에 편집 필드가 없는지 확인합니다.
   목록 상단의 정책 초안·데모 표시와 가게 예약 접수 마감(19:00), 카드의 상품 판매 종료 예시를 구분해 확인합니다.
4. 실제 저장되지 않는다는 안내와 새로고침 시 초기화를 확인합니다.
5. 취소·Escape로 폼을 닫고 포커스 복귀, Tab 이동, 200% 확대를 확인합니다.

## 공통 기반 인계

초기 작성 시 공통 컴포넌트가 없어 화면 전용 CSS Module과 기본 HTML 컨트롤을 사용했습니다. PR 준비 중 최신 main의 공통 UI·루트 레이아웃을 병합했으며, 공통 파일은 이 PR에서 변경하지 않습니다.
색·크기·간격은 DESIGN.md를 따르며 전역 토큰이나 공통 컴포넌트는 만들지 않습니다.
Pretendard 파일은 제공되지 않아 설치된 경우만 적용되고, 그 외에는 시스템 폰트가 사용됩니다.
공통 UI·폰트·공유 타입·수정 계약 확정 후 담당자와 조율해 연결해야 합니다.
이 작업은 UI 데모이며 A03 전체 및 실제 연동 완료가 아닙니다.

## 검증 기록

- `npm run typecheck`: 최초 실행은 통과. 원본 앱 빌드가 `.next/types/validator.ts`를 생성한 후 재실행은 실패했습니다. 기존의 빈 `src/app/(customer)/shop/page.tsx`가 모듈이 아니어서 발생한 오류(TS2306 / TS2344)이며 해당 파일은 변경하지 않았습니다. 격리 앱의 TypeScript 검사는 통과했습니다.
- `npm run lint`: 오류 없음, 기존 `postcss.config.mjs` 경고 1건.
- `npm run test:run`: 렌더링 테스트 7개 통과(기존 정보 분리·가격 읽기 전용 4개와 가게 데모 수정 폼·진입 버튼·변경 공통값 참조 3개). 실제 브라우저 동작 테스트와는 별개입니다.
- main 병합 후 `npm run build -- --webpack`: 컴파일 통과, 기존 빈 customer 페이지의 TS2306 / TS2344로 타입 검사 실패. 기본 Turbopack 빌드는 실행 환경의 포트 생성 권한 오류로 중단됩니다.
- 최신 격리 개발 서버의 `/seller/products`: HTTP 200, 공통 운영 정보·정책 초안·상품 카드 3개 렌더링 확인. 브라우저의 실제 클릭·반응형 확인은 미실행입니다.
- 격리 앱 `preview.mjs --build`: 컴파일·TypeScript·정적 페이지 생성 통과.
- 브라우저 자동 제어 연결 시간 초과로 실제 클릭·반응형·키보드 동작 검증은 미완료입니다. 위 확인 순서로 수동 점검해야 합니다.

원본 앱 기반과 무관하게 화면의 프로덕션 컴파일을 검사하려면 다음을 실행합니다.

```sh
node 'src/app/(seller)/seller/products/preview.mjs' --build
```
