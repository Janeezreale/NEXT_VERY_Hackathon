## 확정 기록

총괄 확정(2026-10-31). 아래에 적지 않은 세부는 표의 미정 상태를 유지합니다.

| ID | 확정 정책 | 남은 미정 |
| --- | --- | --- |
| D01 | 판매자당 매장 1개, 비로그인 상품·매장 조회 허용, 역할은 가입 시 본인 선택. 매장 없는 판매자는 `/store`로 이동하고 등록 전 판매자 화면 차단 | 사업자 확인 |
| D02 | UTC 저장·한국 시간 표시. 마감 기준은 상품 판매 종료와 오늘 가게 마감 30분 전 중 이른 시각이고, 그 시각부터 예약을 막는다. 정확히 2시간 이하는 +12%p, 2시간 초과~4시간 이하는 +5%p, 4시간 초과는 0%p. 등록 경과는 정확히 60분부터, 최근 확정 수량은 정확히 60분 전부터 포함. 취소 수량은 수요에서 제외. 판매 종료는 그날 가게 마감 30분 전을 넘겨 설정할 수 없다(게시·수정 400). 픽업은 예약 마감 전까지. 영업일은 오전 6시에 바뀌고, 06:00 이전 마감은 다음 날 새벽으로 본다 | 없음 |
| D05 | JPG·PNG·WEBP, 5MB, 상품당 1장, 공개 읽기. 브라우저가 Storage에 직접 올리고 버킷이 형식·크기를, 정책이 본인 매장 폴더를 강제한다. AI는 제한 시간 30초, 자동 재시도 없음. 실패해도 직접 입력해 게시한다 | 게시되지 않은 사진 정리 |
| D07 | 리포트 기간은 오늘·최근 7일·최근 30일(한국 날짜). 매출은 판매 완료 금액. 예약 수와 현재 픽업 대기 수를 표시. 수량은 상품별로 표시하고 단위가 다른 수량은 합산하지 않음 | 없음 |
| D13 | 예약 시 이름과 휴대폰 번호를 받는다. 직접 조회 권한은 없고, 판매자는 `reservation_contacts`로 본인 매장의 확정 예약만 읽는다. 끝난 예약의 연락처는 판매자에게 보이지 않는다 | 보관 기간, 파기 |

| D11 | 판매자는 Geocoding으로 주소를 찾고 Web Dynamic Map으로 확인한다. 지역은 `SIGUGUN`에서 정한다. 소비자는 `/shop`의 목록·지도 전환에서 좌표가 있는 등록 매장 전체를 본다. 네이버 장애 시 주소를 직접 입력하고 좌표는 비운다. 좌표는 선택 결과를 저장하고 서버는 범위만 검증한다 | 판매 중 매장으로 좁히기 |

| D15 | 판매자 승인을 없앤다(2026-11-01). 재고를 예약 시 DB 트랜잭션으로 확보해 중복 예약이 불가능하므로 예약은 생성 즉시 `approved`로 확정한다. 화면 표기는 `예약 확정`. `pending`은 쓰지 않고, 과거의 `rejected`·`expired`는 이력으로 표시만 한다. 적용 시 픽업 시각이 지난 대기 예약은 만료, 나머지는 확정했다 | 없음 |
| D16 | 매장에 오픈 시각을 둔다(2026-11-01). 06:00 이상이고, 마감은 오픈보다 늦어야 한다(06:00 이전 마감은 다음 날 새벽). 오픈 전과 예약 마감 후에는 상품과 매장을 그대로 보여주고 안내를 띄워 예약만 막는다(`409 STORE_CLOSED`). 소비자 목록은 영업일(오전 6시 기준) 단위로 그날 상품을 유지하고 다음 영업일에 내린다. 기존 매장의 오픈 시각은 06:00으로 채웠다 | 휴무일 |
| D17 | 소비자가 고른 지역은 `shop-region` 쿠키에 1년 저장한다(2026-11-01). URL에 지역이 없을 때만 복원하고, URL 값이 우선이다. 지역을 비우면 지운다. 서버 권한과 무관한 화면 편의 값이며 저장 목록에 없는 값은 무시한다 | 없음 |
| D08 | 수량은 정수, 금액은 1원 이상(0원 불가). 판매자는 상품명·단위·재고(0 이상)·기준가·최저가·신선도·판매 종료를 수정한다. 재고는 화면에서 본 값이 그대로일 때만 바뀌고, 다르면 `409 STOCK_CHANGED`. 기존 예약의 가격·수량은 유지. 예약 이력이 있는 상품은 삭제 불가. 수량 단위는 자유 입력 | 없음 |

## 기존 문서에서 가져온 검토 후보

아래는 기존 문서의 구체 제안이며 이번 통합으로 확정하지 않습니다.

- D01: 이메일/비밀번호 가입, seller/buyer 역할, 계정당 매장 1개, service_areas 보조 테이블과 지역 API.
- D02: UTC 저장·Asia/Seoul 표시, 최소 15분 후·15분 간격 픽업, 당일 게시 제한, 마감 후 승인 제한.
- D03: 판매자 취소 허용, 승인 예약의 소비자 취소, no_show 상태 추가 여부. 현재 활성 계약의 5개 상태 외에 임의 추가하지 않습니다.
- D04: expected_unit_price 전달과 409 PRICE_CHANGED 재확인 방식.
- D05: Storage SDK 직접 업로드와 서버 업로드 중 선택, 5MB JPG/PNG/WEBP 제한, 한 사진 다품목 분석, AI 실패 시 명시적 수동 등록. 현재 API의 업로드 경로도 이 결정에 종속됩니다.
- D08: 정수 수량·단위 each/box/bunch/stem, 재고 카운터 방식. 어떤 방식을 택해도 요청 시 재고 확보 규칙은 유지합니다.
- D09: Vitest와 npm 검사 스크립트 구성. 모델은 이미지 입력·구조화 출력 지원을 검증한 뒤 지정합니다.

D01 진행 기록(2026-10-31): 사용자 요청에 따라 역할은 가입 시 본인 선택으로 저장하고, 값은 코드·DB 모두 `seller`/`consumer`로 통일합니다(위 후보의 `buyer`는 사용하지 않음). 사업자 확인, 비로그인 탐색, 판매자당 매장 수는 미정입니다.

기존의 100원 단위 입력 제한·내림, 할인율 50% 상한, 승인 시 재고 확보는 원문과 충돌하므로 후보 정책으로 유지하지 않습니다.
