# 통합 검증·시연 체크리스트

[시작 안내](../README.md) · 근거: [기획 원문](../plan.md) §9, §11

현재 모든 항목은 **미검증**입니다. 검증자는 날짜·환경·작업/PR·결과를 기록합니다. 개발용 Supabase에 실제 저장한 테스트 데이터를 사용하고 개인정보·운영 데이터는 시연에 사용하지 않습니다.

## 준비

- [ ] 총괄이 계약·미정 정책을 확정하고 구현 문서에 반영했다.
- [ ] 개발/시연 환경과 판매자·소비자 테스트 계정이 준비됐다.
- [ ] 판매자 매장·지역·주소·마감·픽업 시간이 실제로 저장됐다.
- [ ] 권한 검증용 다른 판매자·소비자 계정도 준비됐다.
- [ ] 환경 변수와 이미지 접근 정책을 배포 환경에서 확인했다.

## 정상 거래 시연

- [ ] 판매자가 로그인하고 실제 상품 사진을 업로드한다.
- [ ] 실제 AI 분석 결과와 불확실성 안내를 확인한다.
- [ ] 판매자가 상품명·수량·단위·신선도를 수정·확인한다.
- [ ] 기준가·최저가·종료 시점을 입력해 게시하고 DB 저장을 확인한다.
- [ ] 소비자가 지역으로 상품을 찾고 실제 가격·수량·매장 정보를 본다.
- [ ] 시간·실제 승인 수요에 따른 가격 변화를 확인한다. 경계값은 가격 테스트에서도 검증한다.
- [ ] 소비자가 수량·픽업 시간으로 예약하면 재고가 확보되고 확정 가격이 저장된다.
- [ ] 판매자가 승인하면 승인 상태가 표시되고 재고가 다시 차감되지 않는다.
- [ ] 현장 결제·수령 후 판매 완료하면 판매 기록이 한 번 생성된다.
- [ ] 리포트의 판매 수량·매출·잔여 재고가 DB 기록과 일치한다.

## 실패·경계·권한

- [ ] 이미지 검증 실패·AI 오류·잘못된 AI 응답에서 가짜 결과를 표시하지 않는다.
- [ ] 상품 0개·예약 0개·판매 0건에서 빈 상태를 표시한다.
- [ ] 재고 부족·판매 종료·잘못된 픽업 시간은 서버에서 차단된다.
- [ ] 마지막 재고를 두 소비자가 동시에 요청해도 초과 예약되지 않는다.
- [ ] 요청 재전송·버튼 중복 클릭으로 예약·판매 기록이 중복 생성되지 않는다.
- [ ] 거절·허용된 취소는 확보 수량을 정확히 한 번 반환한다.
- [ ] 승인과 취소가 동시에 일어나도 확정된 상태 전환과 재고 규칙을 지킨다.
- [ ] 현재가가 변해도 기존 예약의 확정 가격은 유지된다.
- [ ] 가격 계산의 최저가·반올림·시간·수요 경계 테스트가 통과한다.
- [ ] 소비자는 다른 소비자의 예약을 조회·취소할 수 없다.
- [ ] 판매자는 다른 매장의 상품·예약·판매 내역을 수정할 수 없다.
- [ ] UI를 우회한 직접 API·DB·Storage 요청에도 권한 정책이 적용된다.
- [ ] 인증 만료·네트워크 오류에 안내와 안전한 재시도 동작이 있다.
- [ ] 모바일 화면에서 업로드·폼·예약·관리 흐름을 완료할 수 있다.
